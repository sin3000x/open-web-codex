# 仓网数据准备

只在 `$warehouse-single-agent` 第 1 步找不到可复用的准备数据时使用。只准备用户已授权的数据，不计算路线、时效、成本、选址或地图。

## 选择本次需要的数据

- 基线分析需要需求与现有仓。
- 时效、达标率或成本分析，再加入路线或报价。
- 新增单仓、候选仓展示或选址，再加入候选仓。
- 用户要求按真实现状评估时，再加入当前分配关系。
- 用户没说国家时不传 `country_code`；只有用户要求和已确认信息都无法确定国家时才询问，不按文件名或语言猜测。

## 步骤

1. 用 `inspect_workspace_sources` 检查与本次目标有关的原始文件。
2. 为每个需要的数据分别选定确切的 CSV 表、Excel sheet 或 JSON 数组。表头名称不同不是缺数据；含义和类型清楚时，直接写出字段对应关系。
3. 把选定的表和字段对应关系组成 `source_selections`，调用 `prepare_network_input`。行政区目录只用于地理补全，不当作需求或仓库数据。
4. 准备完成后，用返回的 `prepared_input_relative_path` 回到 `$warehouse-single-agent` 第 2 步，不要重复准备。

## 什么时候询问

只在这些情况用一次输入卡片询问，然后停止等待：字段含义有多种解释、单位或币种规则未知、仓型未知、选中的记录缺少业务值、同一标识存在冲突，或工具返回 `needs_input`。没选中的文件和不同的表头都不需要询问。

## 其他结果

- 返回 `source_changed` 时重新检查一次；再次变化就停止，说明来源仍在变化。
- 已确认的候选仓信息不得因基线只计算现有仓而从准备结果中删除。
- 用户只问原始文件本身的字段、记录数、空值或取值时，直接用检查结果回答；问仓网业务数据时，准备后用 `query_prepared_network_input` 查询。
