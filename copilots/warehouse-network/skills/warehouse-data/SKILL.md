# 仓网数据准备

只准备用户已授权的数据，不计算路线、时效、成本、选址或地图。文件读取、校验、身份和写入边界由数据工具负责；本 Skill 只做业务判断。

## 选择本次需要的数据

- 基线分析需要需求与现有仓。
- 用户要求按真实现状评估时，再加入当前分配关系。
- 时效、达标率或成本分析，再加入路线或报价。
- 新增单仓、候选仓展示或选址，再加入候选仓。
- 同一请求先做基线、后做仓变动或选址时，首次准备就同时纳入候选仓，不把已上传的候选仓来源留到后续再次询问。
- 国家只有在用户要求和已确认信息都无法确定时才询问，不按文件名或语言猜测；用户没说国家时不传 `country_code`，已准备的数据自带国家。

## 处理方式

1. 先用 `discover_workspace_sources` 发现来源。列出了准备好的数据（`prepared_candidate`）时，把这些路径和本次需要的数据交给 `resolve_prepared_network_input`；返回 `prepared_ready` 就直接复用，返回 `prepared_unavailable` 或没有准备好的数据时，再用 `inspect_workspace_sources` 检查与本次目标有关的原始来源。
2. CSV 表、Excel sheet 和 JSON 数组分别选择。表头名称不同不是缺数据；只要含义和类型清楚，就提交明确的字段对应关系。
3. 仅在字段含义有多种解释、单位或币种规则未知、仓型未知、选中记录缺少业务值，或同一标识存在冲突时询问。未选择的文件和不同表头都不构成阻塞。
4. 需要新准备数据时，把确切的表、sheet 或数组及字段对应关系组成 `source_selections`，再调用 `prepare_network_input`。行政区目录只用于地理补全，不把它误判为需求或仓库数据。

## 回答数据事实问题

用户只问数据本身（多少个、哪些、按类型或省份分布、需求合计或最高）时，不做规划计算：

1. `discover_workspace_sources` 已列出准备好的数据（`prepared_candidate`）时，不必先检查，直接用 `query_prepared_network_input` 查询；它自己核对来源是否变化。数量用 `group_by`（每组自带精确数量）或 `matched_count`，合计和极值用 `measures`，清单用 `select`、`order_by` 和 `limit`。
2. 结果中的 `roles` 不含所问的数据（例如问候选仓但只准备了现有仓）时，不能把 0 当答案；改查另一份包含该数据的准备结果，没有时先按上面的流程准备再查询。
3. 还没有准备好的数据时，先按上面的流程准备，再查询。
4. 返回 `prepared_input_stale` 时说明来源已变化，重新检查并准备一次后再查询。

检查结果是原始文件映射前、覆盖全部记录的字段统计：用户问原始文件本身的字段、记录数、空值或取值时直接据此回答，不必再查准备好的数据；问仓网业务数据的数量、分布或清单时仍用准备好的数据查询。回答只给数字和统计口径，不附加与问题无关的规划限制。

## 完成或停止

- 工具确认已有数据可复用或准备完成时，原样交接其结果、记录数和警告；不要重复准备。
- 工具要求用户选择来源时，只交接候选项并停止。
- 返回 `needs_input` 时，只交接本次所选数据的真实缺口，不猜值、不循环尝试。
- 返回 `source_changed` 时重新检查一次；再次变化就停止并说明来源仍在变化。

候选仓是否参与本次计算由用户目标决定，但已确认的候选仓信息不得因基线只计算现有仓而从准备结果中删除。
